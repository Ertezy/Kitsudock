# Kitsudock — полировка интерфейса

Дата: 2026-10-03
Статус: согласовано владельцем, готово к написанию плана реализации

---

## 1. Зачем

Приложение работает, но по общему ощущению выглядит «сделано просто». Владелец
(3 октября) выбрал из вариантов именно **общее ощущение**: не отдельный экран, а
то, как всё вместе двигается, откликается и выглядит. Структура экранов
остаётся, новых возможностей нет.

Что даёт это ощущение сейчас (проверено по `src/styles.css`):

- у нажимаемых элементов нет ни одного состояния `:active`, наведение
  оформлено в 7 местах;
- все движения — на одной кривой `ease`;
- 11 разных размеров шрифта (9.5–18 px) и 8 разных скруглений;
- три анимации (карусель баннеров, ещё две) пишут длительность числом мимо
  `--move`, поэтому тумблер «Анимация» их не выключает — это нарушает правило,
  записанное в самих стилях.

Решения владельца (3 октября):

- делается **до первой публикации**: защита сборщика → защита приложения →
  эта полировка → версия 0.1.1 (смена версии переезжает в конец, одна сборка
  и один тег);
- настроение — **«мягко и дорого»**: плавные пружинящие движения, стекло с
  глубиной, мягкая смена фона, лёгкое зерно;
- палитру **можно пересмотреть**: варианты показываются на настоящем
  интерфейсе, владелец выбирает глазами;
- результат смотрим на **стенде предпросмотра** (§3), живое движение владелец
  проверяет в конце на ноутбуке.

Не делаем: перестройку экранов, новые функции, новые зависимости, шрифты из
сети, внешние картинки-заглушки, чужой арт в репозитории.

## 2. Общие правила

- Без новых зависимостей (npm и Cargo). Шрифт Golos уже лежит внутри
  приложения (`@fontsource-variable/golos-text`).
- Все тексты — через `src/i18n`, на русском и английском.
- Анимируются только `transform` и `opacity` (и `filter` у фона, если без него
  никак). Ничего не анимирует `width`, `height`, `top`, `left`.
- Тумблер «Анимация» (вкладка «Вид», `src/lib/motion.ts`, атрибут
  `data-motion` на корне) по-прежнему выключает **всё** движение в одном
  месте: каждая длительность в стилях выводится из переменных движения
  (§4.3). Настройка Windows «уменьшить движение» на приложение не влияет —
  прежнее решение владельца остаётся.
- Существующие тесты остаются зелёными; поведение приложения не меняется.

## 3. Стенд предпросмотра

Служебная страница для разработки: настоящее приложение (те же компоненты и
стили) с тестовыми данными вместо системной части.

- Вход — отдельный `preview.html` со своим `src/preview/main.tsx`. Обычный
  `index.html` и сборка установщика его не включают; Vite раздаёт его только в
  режиме разработки (`npm run dev`, адрес `http://localhost:1420/preview.html`).
- Системная часть подменяется встроенным модулем `@tauri-apps/api/mocks`
  (`mockIPC`, `mockWindows`): на каждую команду, которую вызывает
  `src/lib/api.ts`, стенд отвечает тестовыми данными. Плагины (диалог, буфер,
  ссылки) отвечают заглушками без действия.
- Тестовые данные — в `src/preview/`, синтетические: пять игр с нашими
  названиями и **градиентами-заглушками** вместо фонов и иконок (свои
  нарисованные SVG/градиенты, не арт игр); коды, баннеры, видео с выдуманными
  названиями; одна игра без данных.
- Переключатели состояний на самом стенде (небольшая плашка в углу, видна
  только на стенде): данные грузятся / нет сети / первый запуск / настройки /
  язык ru-en / анимация вкл-выкл / вариант палитры (§4.2).
- Стенд не попадает в собранное приложение — это проверяет тест (§7).
- Тот же стенд потом годится для скриншотов README и записи промо-ролика.

## 4. Система

### 4.1 Шрифт

- Golos остаётся (лучшая кириллица среди подходящих). Используются веса 400,
  500 и 600; 700 — только если без него никак.
- Шкала из пяти размеров, переменными: 11 · 12.5 · 14 · 17 · 22 (крупные — с
  чуть отрицательным межбуквенным интервалом). Любой другой размер в стилях —
  ошибка; размеры, которые считаются от размера дока (подпись иконки,
  буква-заглушка), остаются выражениями от его переменных.
- Цифры в таймерах, датах и счётчиках — `font-variant-numeric: tabular-nums`.
- Подписи-метки: небольшой положительный межбуквенный интервал; заголовки —
  `text-wrap: balance`.

### 4.2 Цвет

Принцип остаётся: **один цвет для действия, другой для содержимого**, и они не
встречаются на одном элементе. Меняются сами значения:

- фон — глубокий тёмный с фиолетовым отливом вместо почти чёрного `#070707`;
- все серые и полупрозрачные слои — в одном сиреневом тоне;
- акцент действия — менее кислотный.

На стенде показываются три варианта (стартовые значения, подбираются по
снимкам и сверяются с иконкой лисы):

| Вариант | Фон | Действие | Содержимое |
|---|---|---|---|
| A «Лисий огонь» | `#0e0b12` | `#ff9d4d` (огненный) | `#e4a6c9` (сакура) |
| B «Янтарь и сирень» | `#0c0b10` | `#f2b84b` (янтарный) | `#b9a3e6` (сирень) |
| C «Нынешняя, спокойнее» | `#0b0a0d` | `#f5c451` | `#d993bf` |

Владелец выбирает один; остальные удаляются из кода. Контраст текста на фоне
и на стекле — не ниже 4.5:1 для основного текста.

### 4.3 Движение

Всё выводится из одной базовой переменной, которую тумблер «Анимация»
обнуляет:

- четыре скорости: быстрая (отклик кнопки, ≈0.12 с), базовая (наведение,
  ≈0.18 с), медленная (появление панели, ≈0.32 с), сценическая (смена фона
  игры, ≈0.6 с);
- две кривые: плавное торможение для появлений
  (`cubic-bezier(0.22, 1, 0.36, 1)`) и лёгкая пружина с микроперелётом для
  нажатий и наведения (`cubic-bezier(0.34, 1.56, 0.64, 1)`);
- длительность числом мимо этих переменных запрещена (тест, §7).

### 4.4 Форма и глубина

- Скругления: 6 (мелкое внутри), 10 (кнопки, поля), 16 (карточки, панель),
  «таблетка» (чипы). Внутренний элемент никогда не скруглён сильнее
  внешнего.
- Три уровня подъёма; тени подкрашены в тон фона, не чёрные.
- Стекло: тонкая светлая кромка сверху (внутренняя тень/рамка), размытие как
  сейчас.
- Зерно: один неподвижный слой поверх всего окна, `pointer-events: none`,
  3–4 % непрозрачности, из SVG-шума в `data:` (CSP это уже разрешает). Не
  мерцает.
- Шкала слоёв (`z-index`) переменными вместо разбросанных чисел.

## 5. Где появляется ощущение

**Главный экран**

- Смена игры: фон перетекает (сценическая скорость) с лёгким «доездом»
  масштаба; подпись над кнопкой и сама кнопка «Играть» появляются чуть позже,
  лесенкой. Крупного названия игры на экране нет и не добавляется — как у
  HoYoPlay, название есть в подписи иконки дока.
- Док: при наведении иконка мягко приподнимается с пружиной, при нажатии
  слегка вдавливается; метка выбранной игры скользит к новой иконке, а не
  перепрыгивает.
- «Играть»: мягкое свечение акцентом при наведении, ощутимое нажатие,
  аккуратное состояние «запускается…».

**Боковая панель**

- Выезжает с пружиной; разделы появляются по очереди.
- Пока данные грузятся — «скелеты» в форме будущих карточек, а не пустота.
- Копирование кода отвечает анимированной галочкой.
- Карусель баннеров — на общих кривых и переменных; превью видео слегка
  приближается при наведении.

**Настройки и первый запуск**

- Переходы между экранами; переключатели с пружинкой; у сегментных кнопок
  выбранная «таблетка» скользит; строки подсвечиваются при наведении.

**Везде**

- У всего нажимаемого есть наведение и нажатие.
- Одинаковые рамки фокуса с клавиатуры (`:focus-visible`), видимые на любом
  фоне.
- Тонкие полосы прокрутки в тон.
- Пустые экраны и ошибки оформлены и с нормальным прямым текстом (без «Упс!»
  и восклицательных знаков).

## 6. Порядок работы

1. Стенд предпросмотра.
2. Токены (§4.1, §4.3, §4.4) — внешне почти ничего не меняется, всё встаёт на
   шкалы.
3. Палитры (§4.2) — три варианта снимками, владелец выбирает.
4. Главный экран. 5. Боковая панель. 6. Настройки и первый запуск. 7. Общий
   проход: состояния, фокус, прокрутка, пустые экраны.

После шагов 3–7 — снимки «до/после» со стенда владельцу. В конце — живая
проверка на ноутбуке (плавность, нагрев, работа тумблера «Анимация»).

## 7. Проверки

- Все нынешние тесты зелёные.
- Новые тесты:
  - стили не содержат длительностей анимаций и переходов числом мимо
    переменных движения;
  - стили не содержат размеров шрифта и скруглений мимо шкал (§4.1, §4.4);
  - стенд не попадает в сборку: после `vite build` в `dist/` нет
    `preview.html` и кода из `src/preview/`;
  - новые тексты есть в обоих языках (существующая проверка i18n
    распространяется на них).
- Производительность: на ноутбуке владельца смена игры и открытие панели без
  рывков; зерно и стекло не дают заметной нагрузки в простое.

## 8. Дополнение: часики сроков и окно после «Играть» (2026-10-26)

Две просьбы владельца после общего прохода, согласованные в чате.

### 8.1 Окно после «Играть»

- По умолчанию окно после запуска игры остаётся открытым: так другую игру
  можно запустить сразу, не доставая окно из трея.
- Переключатель «Уходить в трей после запуска игры» во вкладке «Поведение»
  остаётся. Новое умолчание действует для свежей установки и для конфига без
  блока поведения; сохранённое значение не меняется.
- «Крестик прячет окно в трей» по-прежнему включён по умолчанию.

### 8.2 Пауза, пока окно неактивно

- Пока окно спрятано или не в фокусе (например, человек в игре), стоят видео
  фона, автопрокрутка баннеров и всё бесконечное фоновое движение: медленный
  дрейф картинки, блики, стрелки часиков. Вернулся в окно — всё продолжается.
- Это отдельное условие, а не тумблер «Анимация»: тумблер убирает движение
  совсем, а неактивное окно лишь ставит его на паузу.

### 8.3 Часики сроков

- Карточка кода со сроком и активный баннер получают маленькие часики слева
  от текста срока: кольцо показывает долю оставшегося срока, стрелка
  спокойно бежит по кругу.
- Код: полное кольцо — неделя и больше до сгорания, дальше оно убывает
  линейно. Баннер: доля от всего его срока (от начала до конца).
- Последние сутки: кольцо цвета «сгорающей» карточки, стрелка бежит быстрее.
  Обычное кольцо — цвет содержимого.
- Без часиков: бессрочные коды и баннеры, которые ещё не начались.
- Текст срока не меняется; часики только дублируют его картинкой и скрыты от
  экранного диктора.
- Тумблер «Анимация» выключен — стрелка стоит, кольцо остаётся.
- Движение — только поворот (transform), длительности — от переменных
  движения (§4.3). Кольцо как нетекстовая графика держит контраст ≥3:1 на
  своей карточке.
