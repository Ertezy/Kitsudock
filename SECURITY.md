# Security / Безопасность

## Reporting a vulnerability

Please report suspected security vulnerabilities privately. Do not publish details,
proof-of-concept files or sensitive logs in public issues, discussions or bug reports.

1. Sign in to GitHub and open this repository's **Security (Security and quality) → Report a vulnerability**,
   or use the [private reporting form](https://github.com/Ertezy/Kitsudock/security/advisories/new).
2. Include the Kitsudock version, Windows version, affected component, steps to
   reproduce and the possible impact. Use fictional data where possible and remove
   personal data, passwords and access tokens from attachments.
3. Continue the conversation in the private GitHub report until a fix and public
   disclosure have been agreed with the maintainer.

If **Report a vulnerability** is not available, private reporting may not be enabled
for this repository. Open a [public issue](https://github.com/Ertezy/Kitsudock/issues/new)
asking the maintainer to enable private vulnerability reporting or provide a private
contact method. Include no vulnerability details or attachments in that request;
wait for a private channel before sharing them. This document does not enable the
feature: the repository owner must enable it in GitHub settings.

For ordinary bugs, use the [bug report form](https://github.com/Ertezy/Kitsudock/issues/new?template=bug_report.yml).

## Как сообщить об уязвимости

Сообщайте о возможных уязвимостях приватно. Не публикуйте подробности, примеры
эксплуатации или журналы с чувствительными данными в публичных issues, обсуждениях
или сообщениях об ошибках.

1. Войдите в GitHub и откройте в этом репозитории **Security (Security and quality) → Report a vulnerability**
   или [форму приватного сообщения](https://github.com/Ertezy/Kitsudock/security/advisories/new).
2. Укажите версию Kitsudock, версию Windows, затронутую часть программы, шаги
   воспроизведения и возможные последствия. По возможности используйте выдуманные
   данные; удалите из вложений личные данные, пароли и токены доступа.
3. Продолжайте обсуждение в приватном сообщении GitHub, пока не согласуете с владельцем
   исправление и публичное раскрытие.

Если **Report a vulnerability** недоступна, приватные сообщения могут быть не включены
для этого репозитория. Откройте [публичный issue](https://github.com/Ertezy/Kitsudock/issues/new)
с просьбой включить private vulnerability reporting или предоставить приватный
способ связи. Не указывайте в этой просьбе подробности уязвимости и не прикладывайте
файлы; дождитесь приватного канала, прежде чем передавать их. Этот документ не включает
функцию: владелец должен включить её в настройках GitHub.

Для обычных ошибок используйте [форму сообщения об ошибке](https://github.com/Ertezy/Kitsudock/issues/new?template=bug_report.yml).
